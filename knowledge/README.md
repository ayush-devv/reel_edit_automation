# Editing knowledge base (v1)

This is the expert-knowledge layer of the reel editor (ADR-0027). Claude cannot be retrained, so this layer is what turns a general model into an editor for *this* tool. It has three parts:

1. **Capability catalog** (`capabilities.yaml`): everything that can be done to a reel, with parameters, NLE names, and which part of the stack produces it.
2. **Craft knowledge graph** (`graph/*.yaml`): principles, techniques, anti-patterns, genres, platforms, goals and annotated examples. Each node is a paraphrased rule with a citation, evidence level and confidence.
3. **Provenance** (`drafts/`): the raw research drafts the graph was merged from. They are kept unchanged; do not load them at runtime.

## File layout

```
knowledge/
  SCHEMA.md                      node/capability shapes (v1)
  README.md                      this file
  capabilities.yaml              GENERATED: 221 capabilities
  graph/
    principles.yaml              GENERATED: type principle
    techniques_story_pacing.yaml GENERATED: tech.* except the sound and visual domains below
    techniques_sound_music.yaml  GENERATED: tech.{audio,split,loudness,dialogue,repair,voice,duck,music,sfx,silence,mix,beat}.*
    techniques_color_type_motion.yaml GENERATED: tech.{color,type,caption,motion,transition,punch_in}.* + Devanagari/Hinglish caption nodes
    anti_patterns.yaml           GENERATED: type anti_pattern
    genres.yaml                  GENERATED: type genre
    platforms_goals.yaml         GENERATED: types platform + goal
    examples.yaml                GENERATED: type example (films + reference reels)
    id_map.yaml                  GENERATED: old id → new id (merged nodes; guessed cap ids → catalog ids)
    conflicts.md                 conflict register: every resolution and its reason
  tools/
    merge_plan.yaml              hand-curated: cap id map, cap relabels/patches, new caps, merges, node patches, new nodes
    build_kb.py                  drafts + merge_plan → generated files
    validate_kb.py               validator (CI gate)
    inspect_drafts.py            helper for exploring the drafts
  drafts/                        provenance, never edited
```

**Routing rule:** files are chosen by node `type`. Techniques are further split by the id's domain segment (`tech.<domain>.<name>`), not by which draft they came from.

**Never edit generated YAML by hand.** Change `tools/merge_plan.yaml` (or add a new draft), rebuild, then validate:

```bash
uv run --with pyyaml python knowledge/tools/build_kb.py
uv run --with pyyaml python knowledge/tools/validate_kb.py          # exit 0 = pass
uv run --with pyyaml python knowledge/tools/validate_kb.py --stats  # + count tables below
```

## Schema additions beyond SCHEMA.md v1

| Field | Where | Meaning |
|---|---|---|
| `renderer_owner: engine` | capability | Computed by our Python engine outside both renderers. This covers perception and analysis before render (transcription, VAD, faces/pose/segmentation, SAM 2.1 masks, diarization, stems, beats, de-reverb/denoise models) and engine-side QA measurements. |
| `engine_tool` | capability (required when owner = engine) | Tool or model used: MediaPipe, SAM 2.1, Silero VAD, pyannote, Demucs, beat_this + librosa, mlx-whisper, DeepFilterNet/RNNoise (licence pending), ffprobe/ffmpeg filters run by the engine. |
| `requires_pinned_ffmpeg` | capability (bool, every entry) | True only when the capability needs a library on the ADR-0023 pinned-build list: zscale/libzimg, libplacebo, libass, VideoToolbox. Libraries outside that list (vidstab, rubberband) are called out in `notes`. |
| `decided_by` | capability / node | ADRs that set or override this entry. ADR decisions beat draft research. |
| `genres` | node | The **applies_to** edge (ADR-0027): genres where the rule holds. Empty means genre-agnostic. |
| `avoid_genres` | node (optional) | Genres where the rule must **not** be applied. Used to scope classic film rules against short-form grammar. |
| `enforced_by` | node (optional) | `compiler` (mechanical rule baked into compilation), `qa_gate` (blocking check), `qa_warning`, `reviewer`. |
| `core` | principle (optional) | Always loaded into every Claude call. |
| `merged_from`, `drafts` | node | Provenance: absorbed draft ids and source draft files. |
| `platforms`, `techniques`, `style_vector`, `beats`, `lessons`, `provenance`, `file_held`… | example | Reference-reel fields from `drafts/reference_reels_plan.md` §3.2. |

**Analysis ownership rule:** an `cap.analysis.*` entry is `engine` when it runs before render, even if the engine calls an ffmpeg filter (`engine_tool` names the filter). It is `ffmpeg` only for QA measurements taken on the final render with an ffmpeg filter: loudness, photosensitivity, mono check, contact sheet of the render.

## How it is compiled into Claude calls (ADR-0027 §4)

1. **Classify** the reel's genre (and platform and goals) from the brief, transcript and frames.
2. **Always load the core principles.** These are the 8 nodes with `core: true`: emotion first, positive reason to cut, setup/payoff, first-5-seconds continuation, shot-length variation, dialogue anchors the mix, correct before grade, reading-load ceiling.
3. **Load the genre playbook.** This is the subgraph of techniques, anti-patterns and principles whose `genres` contain the reel's genre, minus nodes listing it in `avoid_genres`, plus genre-agnostic nodes (empty `genres`) relevant to the stage. Follow `requires` edges to pull in prerequisites. Use `conflicts_with` to show Claude the trade-off instead of two contradictory rules. Rank by evidence level, then confidence.
4. **Add 2–3 examples** from `examples.yaml` for the genre, as own-words breakdowns and style vectors, never the media.
5. **Pass the capability catalog** as the action vocabulary. Claude may only request ids that exist, and the compiler routes each one to ffmpeg, Remotion or engine by `renderer_owner`. `unsupported` ids are never planned.
6. **Hand mechanical rules to code, not prose.** Nodes with `enforced_by: compiler` (loudness chain, room tone and edit fades, ducking depth, musical edit, colour pipeline order) are applied by the compiler. Nodes with `qa_gate` or `qa_warning` (true peak, cps, caption-over-face, contrast, safe zone, dead air, skin tone, one enlarged word per line) become deterministic checks (ADR-0006/0017). The Reviewer's rubric is generated from the same nodes.
7. **Learning loop.** Lessons from evaluated reels become proposed edits to `tools/merge_plan.yaml`. They are adopted only if the tuning-set score improves without regressions (ADR-0027 §5). The KB is versioned with the code.

## Copyright and sourcing rule

- **Paraphrase, then cite.** Every node and capability is written in our own words. No copied passages. Quotes are only used when essential, and are ≤ 15 words. Every item carries ≥ 1 source (`title`, `url`, `locator`), and the validator enforces this.
- Reference reels are studied and measured, never redistributed or used for training. Frames and media of third-party reels are not stored in the KB (see `drafts/reference_reels_plan.md` §2). The one current reel example has unverified provenance and must be resolved per that plan's §2.4.
- ADR files and internal analyses are cited by repository path.
